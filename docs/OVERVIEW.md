# Aegis 한눈에 이해하기 (전체 설명서)

> 이 파일 하나로 **이게 뭔지 → 어떻게 보안하는지 → 구조가 어떤지 → 화면(UI)이 어떻게 생겼는지 → 어떻게 테스트하는지**
> 를 쉬운 말로 이해할 수 있게 정리했다. (명령어 중심 실습은 [TEST_GUIDE.md](TEST_GUIDE.md) 참고)

---

## 1. 이게 뭐예요? (한 문단)
**Aegis(아이기스, "방패")는 웹 애플리케이션을 공격으로부터 지키는 "방어막" 프로그램**이다.
직접 공격하는 도구가 아니라, 로그인·요청을 감시하면서 **수상한 트래픽을 막고 → 탐지하고 → 기록**한다.
건물에 비유하면, Aegis는 **입구의 보안 검문소 + 출입증 발급소 + CCTV + 관리실 모니터**를 합쳐 놓은 것이다.

---

## 2. 무슨 공격을 어떻게 막나요? (보안 원리)

| 공격 (쉬운 설명) | Aegis의 방어 (비유) |
|---|---|
| **무차별 대입**: 비번을 계속 찍어서 뚫기 | ① 한 계정 **5번 틀리면 15분 잠금**(금고 잠금) ② 한 IP가 **10번 실패하면 그 IP 자체를 차단**(블랙리스트) |
| **요청 폭주(DoS성)**: 짧은 시간에 요청을 쏟아붓기 | **분당 60회까지만 허용**, 넘으면 429로 거절(입장 인원 제한). 단, 신뢰 IP는 **화이트리스트**로 면제(VIP 프리패스) |
| **SQL 인젝션**: 입력창에 DB 명령을 섞어 넣기 | DB 접근을 **전부 안전한 파라미터 방식(JPA)** 으로만. 문자열로 SQL을 조립하지 않음 → 명령 주입 불가 |
| **XSS**: 악성 스크립트를 화면에 심기 | 화면 출력 시 **자동 이스케이프**(스크립트를 글자로 표시) + **CSP** 헤더로 외부 스크립트 차단 |
| **CSRF**: 사용자 몰래 요청을 위조 | 상태 변경 요청에 **CSRF 토큰** 요구. (헤더 토큰을 쓰는 JWT API는 원리상 안전해서 예외) |
| **클릭재킹**: 투명한 창으로 클릭 가로채기 | **X-Frame-Options: DENY** — 다른 사이트가 Aegis를 iframe에 못 넣음 |
| **자격증명 유출** | 비밀번호는 **BCrypt로 해시**(원문 저장 안 함), 시크릿은 **환경변수**, 로그·에러에 민감정보 안 남김 |

### 인증은 어떻게 동작하나 (출입증 = JWT)
1. 로그인 성공 → Aegis가 **출입증 2개**를 준다: **Access 토큰**(짧게 유효, 30분) + **Refresh 토큰**(길게, 7일).
2. 이후 요청엔 `Authorization: Bearer <Access 토큰>` 을 붙이면 통과.
3. Access가 만료되면 Refresh로 **새 토큰을 재발급**(refresh) — 다시 로그인 안 해도 됨.
4. 권한은 **ROLE_USER / ROLE_ADMIN** 두 등급. 관리자 자원은 ADMIN만, 아니면 **403(접근 거부)**.

### 모든 사건은 "지울 수 없는 일지"에 남는다 (AuditLog)
로그인 성공/실패, IP 차단, 레이트리밋, 권한 거부가 모두 **감사 로그(AuditLog)** 에 기록된다.
기록 항목: **시각 · 행위자(누가) · IP · 종류 · 결과**. 이 일지는 **append-only**(추가만 가능, 수정 불가)라
사후에 조작할 수 없다(CCTV 녹화본 같은 무결성).

## 3. 들어가면 어떤 구조인가요? (아키텍처)

### 3-1. 코드는 6개의 방(패키지)으로 나뉜다
```
com.aegis
├── auth        🔑 로그인/회원가입/JWT/계정 잠금/권한
├── detection   🚨 무차별 대입 탐지·IP 차단·레이트 리미팅·화이트리스트
├── security    🛡️ 보안 설정(필터 순서·헤더·CSRF·접근 규칙)
├── audit       📒 감사 로그(AuditLog) 기록
├── dashboard   📊 관리자 모니터링 API + 웹 화면
└── common      🧩 공통(전역 예외처리, 에러 응답 형식)
```

### 3-2. 요청이 들어오면 거치는 "검문소 순서"
모든 HTTP 요청은 아래 관문을 **순서대로** 통과해야 컨트롤러(실제 기능)에 도달한다.
```
[요청] 
   │
   ▼
① IpBlockFilter      → 차단된 IP인가?         예 → 🚫 403
   │ 아니오
   ▼
② RateLimitFilter    → 분당 한도 넘었나?       예 → 🚫 429
   │ 아니오
   ▼
③ JwtAuthFilter      → Bearer 토큰 확인 → 출입증 부여(있으면)
   │
   ▼
④ CSRF 검사          → 상태변경 요청에 토큰 있나?
   │
   ▼
⑤ 인가(권한) 검사     → 이 경로에 들어갈 등급인가? 아니면 → 🚫 403
   │ 통과
   ▼
[컨트롤러] → [서비스] → [DB / 메트릭]
```
- ①②는 **화이트리스트 IP면 그냥 통과**(검문 면제).
- ③④⑤ 어디서든 막히면 **일관된 에러 형식**(`timestamp/status/code/message`)으로 응답하고,
  내부 오류 내용(스택트레이스)은 절대 노출하지 않는다.

### 3-3. 데이터는 어디에 저장되나 (DB 테이블)
스키마는 **Flyway**로만 관리(자동변경 금지). 주요 테이블:
| 테이블 | 내용 |
|---|---|
| `users` | 계정(아이디, 비번 해시, 권한, 실패횟수, 잠금시각) |
| `blocked_ip` | 차단된 IP와 해제 예정 시각(시간 지나면 자동 만료) |
| `audit_log` | 보안 사건 일지(시각/행위자/IP/종류/결과) — 수정 불가 |
| `flyway_schema_history` | 스키마 변경 이력(Flyway 자동) |

- 개발(dev): **H2**(메모리 DB, 껐다 켜면 초기화) / 운영(prod): **PostgreSQL**.

## 4. 화면(UI)은 어떻게 생겼나요?
Aegis는 크게 **3가지 화면/접점**이 있다.

### 4-1. 일반 API → JSON 응답 (눈에 보이는 화면 X)
대부분의 기능은 REST API다. 예: 로그인하면 이런 JSON이 온다.
```json
{ "accessToken": "eyJ...", "refreshToken": "eyJ...", "tokenType": "Bearer",
  "accessTokenExpiresInMinutes": 30 }
```

### 4-2. Swagger UI — API를 "클릭"으로 테스트하는 화면
브라우저: **http://localhost:8080/swagger-ui.html**
```
┌───────────────────────────────────────────────┐
│ Aegis API  v0.1.0                  [Authorize] │  ← 여기에 토큰 넣으면 보호 자원도 호출
├───────────────────────────────────────────────┤
│ ▸ auth                                          │
│     POST /api/auth/signup    [Try it out]       │
│     POST /api/auth/login     [Try it out]       │
│     POST /api/auth/refresh   [Try it out]       │
│ ▸ account                                       │
│     GET  /api/me                                │
│ ▸ dashboard                                     │
│     GET  /api/admin/dashboard/events            │
│     GET  /api/admin/dashboard/stats             │
└───────────────────────────────────────────────┘
```
→ 각 항목을 펼쳐 **Try it out**으로 실행하고 응답을 바로 본다. 코딩/curl 없이 테스트 가능.

### 4-3. 관리자 대시보드 — 실제 "보안 모니터링 화면"
브라우저: **http://localhost:8080/admin/dashboard** (로그인 `admin` / `admin1234`)
화면 구성(서버 렌더링):

읽어가는 숫자 목록. `aegis_detection_login_failures_total` 같은 우리 카운터가 들어 있다.

## 5. 어떻게 테스트하나요? (요약)
가장 쉬운 순서:
1. `./gradlew bootRun` 으로 기동 → `http://localhost:8080/health` 가 `{"status":"UP"}` 면 OK.
2. **Swagger UI**(`/swagger-ui.html`)에서 회원가입 → 로그인 → Authorize → 보호 자원 호출.
3. **대시보드**(`/admin/dashboard`, admin/admin1234)에서 사건이 쌓이는지 확인.
4. 무차별 대입/레이트리밋 같은 "차단" 테스트는 **맨 마지막에**(막히면 앱 재시작으로 초기화).

➡️ **명령어까지 포함한 17개 항목 전체 시험표는 [TEST_GUIDE.md](TEST_GUIDE.md) 에 있다.**

## 6. 기능 한눈에 (단계별로 무엇을 만들었나)
| 단계 | 한 일 | 핵심 결과물 |
|---|---|---|
| P0 | 프로젝트 골격 | 기본 뼈대, /health |
| P1 | 운영 기반 | 프로파일(dev/prod), Flyway, Actuator/Prometheus, JSON 로그, OpenAPI, 전역 예외처리 |
| P2 | 인증 | 회원가입/로그인, JWT(Access+Refresh), 계정 잠금, 권한 |
| P3 | 탐지 | 무차별 대입 IP 차단, 레이트 리미팅, 화이트리스트, 메트릭, 감사 |
| P4 | 방어 | 보안 헤더, CSRF, 입력검증, SQLi/XSS 점검, 감사로그(행위자·append-only) |
| P5 | 대시보드 | 관리자 모니터링 API + Thymeleaf 웹 화면 |
| P6 | 릴리스 0.1.0 | 테스트·커버리지, Docker, 배포 가이드, 문서(한/영/일) |
| P7 | CI/품질 | GitHub Actions 자동 빌드·테스트, OWASP 의존성 취약점 스캔 |
| P8 | 토큰 수명주기 | Refresh 회전(1회용)·재사용 감지 시 전체 세션 폐기·로그아웃 |
| P9 | 보안 알림 | IP 차단/토큰 재사용 시 웹훅 통지(기본 비활성) |

> 현재 자동화 테스트 **39개** 전부 통과.

## 7. 자주 헷갈리는 점 / 주의
- **시드 계정(admin/user)·H2는 dev 전용**이다. 운영에선 생성되지 않고, 시크릿은 환경변수로 교체해야 한다.
- 테스트 중 갑자기 **403/429** 가 계속 나오면 → IP가 차단됐거나 한도 초과. **앱 재시작**하면 초기화된다.
- 관리자 자원은 반드시 **ADMIN 권한**이 필요(없으면 403). dev에선 `admin/admin1234` 로 확인.
- 이 도구는 **방어·탐지·감사 전용**이며 공격/침투 테스트는 하지 않는다(범위·한계: [SECURITY.md](../SECURITY.md)).
